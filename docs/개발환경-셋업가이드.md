## 0.5 당신의 실제 개발 리그 (M4 Mac Studio + iPhone 16)

> **종합 판정: 이 프로젝트에 거의 이상적인 조합.** M4 Mac Studio는 개발기·튜닝대상을 겸하는 최상급 데스크톱이고, iPhone 16(USB-C)은 외장 계측마이크 직결 경로(D2)를 그대로 지원한다. 아래 특이점만 챙기면 된다.

### ✅ M4 Mac Studio — 개발기이자 "튜닝 대상 소스기기"
- **성능/호환성 제약 0.** M4는 최신 macOS 26(Tahoe)·Xcode 26.4+·Core Audio Taps를 완전 지원한다. 빌드도 빠르다. → **macOS를 최신(26.2+)으로 올리고 Xcode 26.6 설치**가 정석.
- **헤드리스 데스크톱.** 디스플레이·키보드·마우스가 별도 필요(이미 쓰고 계실 것).
- **내장 스피커는 기본 수준.** 그런데 이게 오히려 **이 프로젝트엔 잘 맞는다** — 실제 유스케이스가 "데스크톱 → 외부 스피커"이기 때문이다. **Mac Studio에 외부 2.0/2.1 스피커를 물린 구성이 곧 우리 앱의 표준 테스트 벤치**가 된다.

**출력 연결별 테스트 활용 (장치감지 로직 검증에 유리):**
| 연결 | 무엇에 좋은가 |
|------|---------------|
| **3.5mm 헤드폰잭** (고임피던스 지원) | 가장 간단. 파워드 모니터/2.1로 바로 스테레오 테스트 |
| **USB DAC** | 고음질 + **USB 출력장치 감지 로직** 검증(외부 장치명·채널수 조회) |
| **HDMI 2.1** → AVR/사운드바 | 멀티채널 패스스루 경로(**v2 5.1/7.1** 사전 실험) |
| **Thunderbolt/USB-C 오디오 IF** | 프로 인터페이스 경유 출력 테스트 |

> 이 여러 출력을 번갈아 물려보면 §4.2의 **출력장치 자동 감지(2.0/2.1 판별)** 를 실제 하드웨어로 검증할 수 있다. Mac Studio 하나로 다양한 출력 시나리오를 커버하는 셈.

**측정 시 주의(중요):** 헬퍼앱이 ① 시스템오디오를 Tap으로 캡처해 EQ를 걸고, 동시에 ② 측정용 스윕을 같은 출력장치로 재생한다. **측정(스윕 재생) 중에는 반드시 EQ를 바이패스**해서, "보정 안 된 원음 룸 응답"을 측정하도록 한다(안 그러면 EQ가 반영된 응답을 다시 측정하는 순환 오류). 개발명세서 §7 워크플로에 이미 반영됨 — 구현 시 상태머신으로 강제.

### ✅ iPhone 16 (일반 모델) — 외장 계측마이크 직결 OK
- **USB-C 있음.** iPhone 15부터 USB-C라 **계측마이크 직결 경로가 열려 있다**(D2의 정밀 경로 실현 가능). 일반 모델의 USB-C는 데이터 속도가 **USB 2.0(480Mbps)** 이지만, **오디오 클래스 장치는 대역폭이 작아 전혀 문제되지 않는다**(속도 제한은 대용량 파일전송에만 영향).
- **A18 칩** — vDSP FFT/디컨볼루션 실시간 처리에 차고 넘친다.
- **iOS 버전** — iPhone 16은 iOS 18로 출시되어 현재 26.x. iOS 17.4+ USB Audio Class 지원 → **iMM-6C 등 계측마이크를 어댑터 없이 바로 인식.**
- **주의 — 캘리브레이션 데이터 없음:** 우리가 확보한 실측 데이터는 iPhone 15 Pro Max 기준이라, **iPhone 16 일반 모델 내장 마이크의 보정 프로파일은 직접 만들어야 한다**(아래 M1 참조).

### 🎯 이 리그 기준, 준비물 우선순위 조정
| 우선 | 항목 | 메모 |
|------|------|------|
| 이미 보유 | M4 Mac Studio + iPhone 16 | 그대로 최상급 개발 리그 |
| 확인 | 외부 모니터·키보드·마우스 | Mac Studio는 헤드리스 |
| **M1 전 구매 권장** | **USB-C 계측마이크 1개** (Dayton **iMM-6C** ~$40 입문 / **UMIK-1·2** 레퍼런스급) | iPhone 16 USB-C에 직결. 정확도 검증 + iPhone 16 프로파일 제작에 필수 |
| 준비 | 외부 2.0 또는 2.1 스피커 | Mac Studio 출력 테스트 대상 |
| 준비 | 소형 삼각대 | 마이크 거치 |

### 🔧 로드맵 반영 (개발명세서 §13 대비 구체화)
- **M0 PoC:** Mac Studio에서 스윕 재생 ↔ iPhone 16으로 캡처 → 처음엔 **3.5mm잭에 물린 파워드 스피커 + iPhone 내장 마이크**로 가장 단순하게 파이프라인(동기·IR 추출) 검증.
- **M1 캘리브레이션(당신 리그 특화):** **iPhone 16(내장마이크)** 측정치를 **iMM-6C/UMIK(레퍼런스)** 와 동시 비교해 오차를 정량화하고, 그 역보정을 **"iPhone 16 일반 모델" 캘리브레이션 프로파일 1호**로 앱에 내장. 신뢰 대역(R8) 경계도 이 실측으로 확정.
- **테스트 매트릭스 한계 인지:** 현재 기기는 iPhone 16 1대 + Mac Studio 1대. v1은 이 조합에 최적화해 출시하되, **캘리브레이션 프로파일 시스템은 다른 iPhone 모델을 나중에 추가할 수 있게 확장형으로 설계**(모델ID → 프로파일 매핑 테이블)한다.

## 1. 큰 그림 — 무엇을 왜 설치하나

이 프로젝트는 앱이 **두 개**입니다.
- **iOS 앱** (SwiftUI) — 아이폰에서 마이크로 측정
- **macOS 헬퍼앱** (Swift/AppKit) — 맥에서 재생·EQ 적용

둘 다 **Swift 언어 + Xcode**로 만듭니다. 그래서 세팅은 대부분 "Xcode 하나를 제대로 깔고, 서명(코드사이닝)을 설정하고, 실기 테스트 경로를 뚫는 것"으로 요약됩니다. 웹개발처럼 도구를 여러 개 조합할 필요가 거의 없고, **Xcode가 에디터·컴파일러·시뮬레이터·디버거·배포도구를 다 포함**합니다.

```
[Mac] ── Xcode ──┬── iOS 앱 빌드 ──▶ [iPhone 실기]에 설치·디버그
                 └── macOS 앱 빌드 ──▶ [이 Mac]에서 바로 실행·디버그
```

## 2. 하드웨어 요구사항 (상세)

### 2.1 Mac (필수)
- **칩:** **Apple Silicon(M1 이상) 강력 권장.** Intel Mac은 macOS 지원이 종료 단계라 신규 프로젝트에 부적합.
- **왜 이 Mac이 중요한가:** Xcode를 돌리는 개발기이자, **이 프로젝트의 macOS 헬퍼앱을 테스트하는 대상 기기**다. 즉 개발용 Mac = 튜닝 솔루션의 "소스기기" 역할을 겸한다.
- **macOS 버전(개발기):** 최신 Xcode 26을 쓰려면 Mac이 비교적 최신 macOS여야 한다.
  - Xcode 26.4 이상 → **macOS Tahoe 26.2 이상** 필요
  - Xcode 26.0–26.3 → macOS Sequoia 15.6 이상
  - **권장:** Mac을 최신 macOS(26.x)로 업데이트해두면 가장 매끄럽다.
- **저장공간:** Xcode + 시뮬레이터로 **약 40GB 이상** 여유 권장(디스크 넉넉할수록 편함).
- **RAM:** 16GB 이상 권장(8GB도 가능하나 빌드가 느림).

> ⚠️ **개발기 macOS 버전 vs 앱의 최소 지원 버전은 별개다.**
> 우리 앱은 **macOS 14.2 이상**을 "지원"(deployment target)하지만, 그 앱을 **만드는 Mac**은 최신 macOS(26.x)를 쓰는 게 정상이다. Xcode에서 "이 앱은 14.2부터 돌아감"이라고 설정하면, 최신 Mac에서 만들어도 구형 macOS에서 실행되는 앱이 나온다.

### 2.2 iPhone 실기 (필수)
- **이 프로젝트는 시뮬레이터로 개발이 거의 불가능하다.** 이유:
  - 시뮬레이터에는 **실제 마이크 하드웨어가 없다** → 룸 측정의 본질을 테스트 못 함
  - `.measurement` 모드, 마이크 데이터소스 선택, USB-C 오디오 등 **하드웨어 의존 기능**이 시뮬레이터에서 동작하지 않음
- **권장 기종:** **iPhone 15 이상(USB-C).** iOS 17.4의 USB Audio Class 지원으로 계측마이크를 어댑터 없이 직결 가능. (12~14 Lightning 기종은 어댑터 필요 → 실용성↓)
- **iOS 버전:** 앱 최소 지원은 iOS 17이지만, 실기는 최신(현재 26.5.x)이어도 무방(하위호환 설계).

### 2.3 측정 주변기기 (권장, M1 단계부터)
- **USB-C 계측마이크:** Dayton Audio **iMM-6C**(약 $40, 가성비) 또는 miniDSP **UMIK-1/UMIK-2**. per-unit 캘리브레이션 파일 포함.
- **삼각대:** 마이크를 청취 위치 귀 높이에 고정(반복성 확보).
- **테스트용 스피커:** 개발 초기엔 Mac 내장 스피커로도 파이프라인 검증 가능. 실제 튜닝 테스트는 2.0/2.1 스피커 세트.

## 3. 소프트웨어 설치 — 단계별

### STEP 1. macOS 업데이트
`  Apple 메뉴 → 시스템 설정 → 일반 → 소프트웨어 업데이트`
→ 최신 버전으로 업데이트(Xcode 26 요구사항 충족).

### STEP 2. Xcode 설치
두 가지 방법:
- **(쉬움) App Store:** "Xcode" 검색 → 설치. 자동 업데이트 편리.
- **(권장, 버전관리) developer.apple.com:** [developer.apple.com/xcode](https://developer.apple.com/xcode/) 또는 [xcodereleases.com](https://xcodereleases.com/)에서 특정 버전 `.xip` 다운로드. 여러 Xcode 버전 병행 관리에 유리.
- **현재 최신:** Xcode **26.6** (iOS 26.5 SDK 포함). App Store 제출은 **iOS 26 SDK 이상 필수**(2026-04-28부터)이므로 반드시 Xcode 26을 쓴다.
- 설치 후 최초 실행 시 추가 컴포넌트 설치에 동의.

### STEP 3. Command Line Tools
Xcode 설치 후 터미널에서:
```bash
xcode-select --install       # 명령줄 도구(git, clang 등)
xcodebuild -version          # 설치 확인
sudo xcodebuild -license accept   # 라이선스 동의(최초 1회)
```

### STEP 4. Apple Account 로그인 (Xcode에)
`  Xcode → Settings(설정) → Accounts → + → Apple Account`
- 본인 Apple 계정으로 로그인. **이 단계까지만 해도 무료로 실기 테스트가 가능**(Personal Team).

### STEP 5. (권장) Homebrew & git
```bash
# Homebrew (부가 도구 설치용 패키지 매니저)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# git 사용자 정보(커밋 서명용)
git config --global user.name  "이름"
git config --global user.email "younghaen.code@gmail.com"
```
> 이 프로젝트는 외부 라이브러리 의존이 거의 없어(아래 §7) Homebrew는 선택이다. 다만 git·부가도구를 위해 깔아두면 편하다.

## 4. Apple 계정 & 개발자 프로그램 — 무료 vs 유료

### 4.1 무료(Apple Account만)로 할 수 있는 것
- **본인 아이폰에 앱 설치 & 디버깅** (Personal Team, "free provisioning")
- Xcode의 대부분 기능, 시뮬레이터
- **제약:**
  - 프로비저닝 프로파일이 **7일 후 만료** → 앱을 다시 빌드·설치해야 함
  - 등록 가능한 App ID **10개 제한**
  - 일부 고급 기능(푸시, iCloud, App Groups 등) 사용 불가

### 4.2 유료 Apple Developer Program ($99/년)이 필요한 시점
이 프로젝트에서는 **결국 필요**하다. 특히:
- **macOS 헬퍼앱 배포**: App Store 밖 직접 배포에는 **Developer ID 인증서 + 공증(notarization)** 이 필수인데, 이는 **유료 회원만** 발급받는다. (Core Audio Tap도 서명된 바이너리를 요구.)
- **TestFlight** 베타 배포, **App Store** 출시
- 7일 만료 없는 안정적 프로비저닝

**추천 타이밍:** M0~M1(로컬 프로토타이핑) 동안은 **무료로 시작**하고, 무선 통신·Mac 헬퍼를 실제로 돌리고 배포를 준비하는 **M2~M4 시점에 유료 가입**한다. (교육기관/비영리는 fee waiver 가능.)

## 5. 코드 서명(Code Signing) — 입문자가 알아야 할 최소 개념

iOS/macOS는 "누가 만든 앱인지" 서명으로 검증한다. 처음엔 복잡해 보이지만 실무는 대부분 **자동**이다.

- **핵심 3요소:**
  - **Bundle ID**: 앱 고유 식별자 (예: `com.younghaen.roomtune`, `com.younghaen.roomtune.helper`)
  - **Team**: 서명 주체(무료=Personal Team, 유료=Developer 팀)
  - **Signing Certificate / Provisioning Profile**: 서명 자격 (Xcode가 자동 생성·갱신)
- **실무 설정:** Xcode 프로젝트 → 타깃 선택 → **Signing & Capabilities** 탭 → **"Automatically manage signing"** 체크 → Team 선택. 대부분 이걸로 끝.
- **Capabilities(기능 권한)** 도 이 탭에서 추가한다(§6).

## 6. 이 프로젝트 전용 Xcode 설정

### 6.1 프로젝트 구조
- Xcode에서 **하나의 프로젝트(또는 워크스페이스)** 안에 타깃 2개:
  - `RoomTune`(iOS App) — deployment target **iOS 17.0**
  - `RoomTuneHelper`(macOS App) — deployment target **macOS 14.2**
- 공통 코드(측정 데이터 모델, 통신 메시지 스키마 등)는 **Swift Package 또는 공유 프레임워크**로 분리해 두 타깃이 공유.

### 6.2 iOS 앱에서 켜야 할 설정 (Signing & Capabilities / Info.plist)
| 항목 | 위치 | 값/설명 |
|------|------|---------|
| 마이크 권한 문구 | Info.plist | `NSMicrophoneUsageDescription` = "룸 측정을 위해 마이크를 사용합니다" |
| 로컬 네트워크 문구 | Info.plist | `NSLocalNetworkUsageDescription` = "Mac 헬퍼와 통신합니다" |
| Bonjour 서비스 | Info.plist | `NSBonjourServices` = `_roomtune._tcp` |
| 백그라운드 오디오 | Capabilities | Background Modes → **Audio** 체크 |

### 6.3 macOS 헬퍼앱에서 고려할 설정
- **Hardened Runtime** (공증 필수 조건) + **오디오 입력** 관련 entitlement
- **시스템 오디오 캡처(Core Audio Taps)** 권한 — 최초 실행 시 사용자 승인 유도
- 메뉴바 앱: `LSUIElement = YES` (Dock 아이콘 숨김)
- 배포 시 **Developer ID 서명 + notarization**

> ⚠️ Core Audio Taps / 시스템 오디오 캡처의 **정확한 entitlement 조합은 Apple 최신 문서로 확인**해야 한다(개발명세서 §14 리스크 항목). 로컬 개발·디버깅은 Xcode에서 바로 빌드·실행하면 되고, 서명·공증은 배포 단계에서 처리한다.

## 7. 의존성 관리 (좋은 소식: 거의 필요 없음)

이 프로젝트의 핵심 기능은 **Apple 내장 프레임워크만으로 구현**된다 → 외부 라이브러리 리스크가 적다.

| 기능 | 프레임워크 | 비고 |
|------|-----------|------|
| 오디오 재생/녹음 | AVFoundation (AVAudioEngine/Session) | 내장 |
| DSP (FFT/디컨볼루션) | **Accelerate / vDSP** | 내장 |
| 장치 감지/시스템오디오 | Core Audio (HAL, Taps) | 내장 |
| 통신 (Bonjour/WebSocket) | Network.framework | 내장 |
| 저장 | SwiftData / Core Data | 내장 |

- 패키지가 필요해지면 **Swift Package Manager(SPM)** 사용: Xcode → File → Add Package Dependencies. (CocoaPods 같은 구식 도구는 불필요.)
- 예: 차트 시각화를 커스텀 대신 라이브러리로 하고 싶을 때 정도. 그 외엔 내장으로 충분.

## 8. 실기 테스트 워크플로

### 8.1 아이폰 연결
1. USB-C 케이블로 iPhone ↔ Mac 연결
2. iPhone에서 "이 컴퓨터를 신뢰" 승인
3. iPhone: 설정 → 개인정보 보호 및 보안 → **개발자 모드** 켜기(최초 1회, 재부팅)
4. Xcode 상단 실행 대상(scheme)에서 연결된 iPhone 선택 → **Run(⌘R)**
5. 최초 설치 시 iPhone: 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 **신뢰**
6. 이후 **무선 디버깅**도 가능(같은 Wi-Fi, Xcode에서 "Connect via network" 체크)

### 8.2 macOS 헬퍼 테스트
- 같은 Xcode에서 헬퍼 타깃을 선택해 **⌘R** → 개발 중인 Mac에서 바로 실행. 별도 기기 불필요.

### 8.3 통합(iPhone↔Mac) 테스트
- iPhone 앱과 Mac 헬퍼를 **동시에 실행**하고 같은 Wi-Fi에 두면 Bonjour로 서로 발견. (초기엔 Mac에서 헬퍼 실행 → iPhone에서 Run.)

> **시뮬레이터의 위치:** UI 레이아웃·네비게이션 확인 정도엔 유용하지만, **측정·오디오·통신 검증은 반드시 실기**로 한다.

## 부록. 자주 막히는 지점 (FAQ)

- **"Untrusted Developer" 오류** → iPhone 설정에서 개발자 앱 신뢰(§8.1-5).
- **7일 뒤 앱이 안 열림** → 무료 계정의 프로비저닝 만료. 재빌드하거나 유료 가입.
- **시뮬레이터에서 마이크가 안 됨** → 정상. 실기로 테스트해야 함.
- **Mac 헬퍼가 시스템 오디오를 못 잡음** → 시스템 오디오 캡처 권한 승인 필요 + 서명된 빌드 필요(개발 중엔 Xcode 실행 빌드 사용).
- **iPhone이 Xcode에 안 보임** → 케이블/신뢰/개발자 모드 확인, Xcode의 Devices 창(Window → Devices and Simulators) 점검.
