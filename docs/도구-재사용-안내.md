# 소스빌드 DCP-o-matic 도구 재사용 안내 (같은 맥의 다른 프로젝트)

> 소스빌드한 DCP-o-matic 도구를 **이 맥의 다른 프로젝트에서 가져다 쓰는** 방법.
> 시나리오: **같은 맥에서 참조** (재빌드·패키징 불필요).

## 두 가지 빌드가 있다 — 헷갈리지 말 것
| 빌드 | 위치 | 용도 |
|------|------|------|
| **정식(stock)** — EQ 없음 | `~/src/dcpomatic-stock/build/src/tools/` (`$DCPOMATIC_TOOLS`) | **일반 용도 / GPU J2K 인코딩 프로젝트** — 중간산출물 확인 Player + 인코딩 CLI |
| 룸튜닝(EQ) | `~/src/dcpomatic/build/src/tools/` (`$ROOMTUNE_TOOLS`) | 재생 경로에 룸 EQ가 들어간 변형 (별개 프로젝트) |

> **GPU 인코딩 프로젝트에서 쓸 건 "정식(stock)" 빌드다.** 아래는 정식 기준.

---

## 30초 요약
1. 정식 도구 → **`~/src/dcpomatic-stock/build/src/tools/`**
2. **제자리에서 절대경로로 호출**하면 끝. env 소싱·설치 불필요(dylib 절대경로 링크).
3. 편의: `source /Users/homedcp/Claude/Projects/roomtunning/scripts/roomtune-tools.env.sh` → `dcpm-player "/DCP경로"`, `dcpm-cli ...`

---

## 1. 정식 빌드 도구 (`$DCPOMATIC_TOOLS`)
| 도구 | 용도 |
|------|------|
| **`dcpomatic2_player`** | **DCP/중간산출물 재생·확인 (정식, EQ 없음)** |
| **`dcpomatic2_cli`** | **CLI 인코딩 (GPU 인코딩 테스트 베이스)** |
| `dcpomatic2` | 메인 GUI (DCP 생성/인코딩) |
| `dcpomatic2_create` | 필름/DCP 생성 CLI |
| `dcpomatic2_server` / `dcpomatic2_server_cli` | **분산 인코딩 서버 (인코딩 워커)** |
| `dcpomatic2_verifier` | DCP 검증 |
| `dcpomatic2_kdm` / `_kdm_cli` | KDM 생성 |
| `dcpomatic2_batch` / `_combiner` / `_map` / `_editor` / `_playlist` | 배치/조합/매핑/편집/재생목록 |

## 2. 호출 방법
```bash
source /Users/homedcp/Claude/Projects/roomtunning/scripts/roomtune-tools.env.sh

dcpm-player "/Users/homedcp/Desktop/어떤DCP폴더"    # 중간산출물 확인 (정식 Player)
dcpm-cli --help                                     # 인코딩 CLI
"$DCPOMATIC_TOOLS/dcpomatic2_verifier" "/DCP경로"

# 소싱 없이 절대경로 직접 호출도 동일하게 동작
~/src/dcpomatic-stock/build/src/tools/dcpomatic2_cli --help
```
- 다른 프로젝트의 스크립트/Makefile: `DCPOMATIC_TOOLS=$HOME/src/dcpomatic-stock/build/src/tools` 로 두고 `"$DCPOMATIC_TOOLS/도구명"` 호출.

## 3. 반드시 지킬 규칙 ⚠️
- ✅ **제자리에서 실행** (`~/src/dcpomatic-stock/build/src/tools/`).
- ❌ **바이너리만 딴 곳으로 복사 금지** (dylib 절대경로·리소스 못 찾음).
- ❌ **build 디렉토리 이동/`./waf distclean` 금지** (산출물·리소스 소멸).
- 리소스는 `~/src/dcpomatic-stock/build/src/Resources/`에 있어야 함(실행파일 기준 `../Resources` 자동 탐색 → **cwd는 무관**).

## 4. 런타임 주의점
- **env 소싱 불필요:** dylib가 절대경로(`/opt/homebrew/...`, `~/dcpomatic-env/lib`, `~/src/*/build`)로 링크됨. 그 경로들이 유지돼야 함(brew 삭제/이동 금지).
- **설정 공유:** `~/Library/Preferences/com.dcpomatic/` 를 공식 설치앱과 공유. (정식 빌드는 EQ 빌드의 DKDM 크래시 이슈와 무관.)
- 일부 CLI는 cwd에 따라 무해한 `fatal: ...`(git) 경고를 낼 수 있으나 기능엔 지장 없음.

## 5. GPU J2K 인코딩 프로젝트 참고
- **중간산출물 확인:** `dcpm-player`로 만들어진 DCP/프레임을 재생·검증.
- **인코딩 경로:** J2K 인코딩은 CLI(`dcpomatic2_cli`)·분산서버(`dcpomatic2_server`)를 통해 수행됨. GPU 연산을 붙이려면 **소스의 J2K 인코드 지점**을 수정해야 한다(`libdcp`의 `dcp::compress_j2k` / dcpomatic의 `J2KEncoder` 계열). 이 경우 정식 소스(`~/src/dcpomatic-stock`, `~/src/libdcp`)를 베이스로 별도 포크 권장 — 정확한 삽입 지점 탐색은 요청 시 지원.
