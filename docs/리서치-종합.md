# 리서치 종합 (Research Digest)

## Part 1. 룸튜닝 음향학 이론

- **대역 분리 원칙:** 슈뢰더 주파수 `fs ≈ 2000·√(RT60/V)`(RT60 초, V m³) 이하는 룸모드(정재파)가 지배(15~25dB 피크/딥) → **EQ 대상(피크)**. 그 이상은 반사가 통계적으로 겹쳐 위치 극민감 → **흡음·배치**. 소형 거실 fs ≈ 150~250Hz.
- **딥은 EQ로 못 채운다:** 상쇄로 생긴 딥(null)은 비최소위상 → 부스트하면 반사도 커져 상쇄 유지, 헤드룸 소진·클리핑. **피크 cut 우선, 넓고 얕은 딥만 소폭.**
- **축 모드** `f = n·c/(2L)` (c=343m/s)로 룸 치수에서 직접 계산. 축>접선(-3dB)>사방향(-6dB).
- **SBIR**(딥 `f=c/2d`)·조기반사·RT60은 시간영역/위치의존 → EQ 불가, 배치·흡음.
- **타깃 커브는 플랫이 아님:** 음악=Harman 하향틸트(약 -1dB/oct)+저역 룸게인(+4~8dB); 시네마=SMPTE X-curve(2kHz부터 -3dB/oct, **소형룸은 -1.5dB/oct 또는 4kHz부터** 완화형).
- 출처: REW 공식문서(iseqtheanswer), Toole/Olive, SMPTE ST 202, GIK Acoustics.

## Part 2. 측정·보정 알고리즘

- **측정신호:** Farina **ESS(지수 사인 스윕)** → 역필터 디컨볼루션으로 IR 추출. 고조파 왜곡을 시간축 분리, MLS보다 SNR·왜곡제거 우수.
- **공간 평균 필수:** 단일지점 금지. **MMM(Moving Mic Method)** 우선 또는 다지점(Audyssey 8~32, Dirac 9~17). Audyssey는 퍼지 클러스터링으로 공통 피크/딥만 보정.
- **필터:** 심리음향 스무딩(저역 1/3oct·고역 1/6oct 가변)→피크 검출→**biquad PEQ(최소위상)** 자동 배정. FIR(혼합/선형위상)은 프리링잉·레이턴시 트레이드오프 → 고급 옵션.
- **과보정 방지:** 게인 상한(예 +6dB), preamp 음수게인.
- 출처: Farina AES, REW, Dirac/Audyssey/Trinnov/Sonarworks 문서.

## Part 3. 멀티채널 캘리브레이션 (2.0/2.1/5.1/7.1)

- **배치:** ITU-R BS.775(프론트 ±30°, 센터 0°, 서라운드 100~120°) + Dolby(7.1 리어 135~150°).
- **레벨:** 채널별 핑크노이즈(-30dBFS 기록), 가정 75dB/시네마 85dB, C-Slow. 스피커 감도차 보정.
- **딜레이:** 343m/s(2.9ms/m, 48kHz서 1ms≈48샘플). **서브는 DSP로 +3~10ms 추가지연** → 실측 필요.
- **베이스 매니지먼트:** THX 크로스오버 80Hz, LFE LPF 120Hz(별개). Small/Large 판정.
- **서브 위상정합:** 폴라리티 반전 시 크로스오버 딥 최소화(REW Aligned Sum). 이 딥은 EQ로 못 고침.
- **채널별 EQ:** 서브는 반드시 개별, 메인/서라운드는 개별 또는 공통 하우스커브.
- 출처: ITU-R BS.775-4, Dolby, THX, Audioholics, Acoustic Frontiers.

## Part 4. 아이폰 마이크 적합성 (이원 전략)

- **기종은 병목 아님:** iPhone 12~16 마이크 3곳(하단/전면/후면) 배치 유사. 병목은 내장 마이크 자체.
- **저역 한계 원인:** "MEMS라서"가 아니라 **Apple 통화용 HPF/DSP + 무캘리브레이션**. 실측 ~100Hz부터 롤오프, 20Hz에서 -15dB+, 고역 회절 지향성.
- **`.measurement` 모드:** AGC/신호처리 최소화하나 **응답을 평탄하게 만들지 않음** → 캘리브레이션 역보정 필수.
- **이원 전략:** (A) 내장=편의/입문, 100Hz~1kHz 실용 / (B) **iPhone 15+ USB-C 직결 계측마이크**(Dayton iMM-6C ~$40, UMIK-1/2)=20~50Hz 심저역·정밀. iOS 17.4 USB Audio Class로 드라이버 없이 직결, 버스파워 ≤500mA.
- **정확도 근거:** Kardous & Shaw(JASA 2016) — 오차 주원인은 마이크, 외장 계측마이크로 대폭 개선.
- **측정 실무:** 삼각대·귀 높이·경계면 30cm 이격, cal 있으면 정면(0°)/없으면 상방 랜덤인시던스.
- 출처: Faber Acoustical 실측, Knowles AN22, Kardous & Shaw JASA, miniDSP, audioXpress.

## Part 5. macOS 오디오 통합

- **출력장치 감지:** Core Audio HAL(`kAudioHardwarePropertyDefaultOutputDevice`, `kAudioDevicePropertyStreamConfiguration`)로 채널수 조회 → 2.0/2.1/5.1/7.1 자동판별. **브라우저 불가 → 네이티브 필수.**
- **시스템 전역 EQ 공개 API 없음**(정확). 그러나 **macOS 14.2+ Core Audio Taps(`AudioHardwareCreateProcessTap`)로 가상 드라이버 없이** 캡처→EQ→aggregate device 재출력 가능(iQualize 실증). "AudioServerPlugIn 가상드라이버 필수"는 **부정확**. 구형 13 이하만 BlackHole형 필요.
- **테스트톤 라우팅:** `AudioDeviceCreateIOProcIDWithBlock`(AVAudioEngine CurrentDevice 지정은 버그).
- **로컬 통신:** Bonjour/mDNS + WebSocket, iOS는 `NSLocalNetworkUsageDescription`/`NSBonjourServices`.
- 출처: Apple Core Audio 문서, eqMac/BackgroundMusic/BlackHole, Rogue Amoeba ARK, iQualize.

## Part 6. DCP-o-matic 내부구조 (포크 타당성)

- **오디오 백엔드:** **RtAudio(Core Audio API)**, 인터리브 float32 48kHz, 블록 1024.
- **EQ 삽입 지점(확정):** `src/wx/film_viewer.cc`의 오디오 콜백, `_butler->get_audio(...)` 직후(약 742행). **재생 전용** — 여기 넣으면 EQ가 **수출 DCP에 안 섞임**(B-chain 절대요건). Player도 이 뷰어로 재생.
  - ❌ `src/lib/player.cc:1240`(AudioProcessor 경로)는 **인코딩과 공유** → EQ가 DCP에 구워짐. 금지.
- **기존 EQ 없음:** 선형위상 FIR(windowed-sinc, 업믹서 전용)·`AudioDelay`(정수샘플)·콘텐츠 스칼라 gain·믹싱 매트릭스만. **파라메트릭 EQ·채널별 gain/delay는 신규 작성**(수백 줄, biquad).
- **채널맵(libdcp):** 0=L,1=R,2=C,3=LFE,4=Ls,5=Rs,6=HI,7=VI,8/9=Lc/Rc,10/11=BsL/BsR… 최대 16.
- **라이선스:** **GPL-2.0-or-later**. 내부사용 무제한, 배포 시 소스 공개 의무.
- **빌드:** waf. macOS는 osx-environment(~40 라이브러리)+cdist+패치 FFmpeg가 공식 경로. **패치 FFmpeg는 라우드니스 전용(`mandatory=False`)** → 우리 용도엔 생략 가능. 자매 라이브러리 핀버전(libdcp 1.10.58 등)은 소스빌드. 일반 사용자 arm64 from-source 공개 성공사례 없음.
- 상세 빌드: [DCP-o-matic-빌드계획.md](DCP-o-matic-빌드계획.md).

## Part 7. EQ 적용 경로 4안 비교 (핵심 의사결정)

| 경로 | 노력 | 비용 | 디스크리트 멀티채널 | 정밀도(B-chain/X-curve) | 유지보수 |
|------|------|------|-----------------------|--------------------------|----------|
| **1. Audio Hijack/SoundSource + AU EQ** | 낮음 | $49~69 | ✗ **스테레오 파이프라인**(다운믹스) | 스테레오만 → B-chain 실격 | 낮음 |
| **2. 하드웨어 DSP(miniDSP/Trinnov)** | 중 | $600~1,100(+DAC) | ✓ 8ch 디스크리트 | ✓✓ 채널별 EQ+레벨+딜레이, X-curve | 매우 낮음(set&forget) |
| **3. DCP-o-matic 포크** | (삽입)낮음/(빌드)높음 | $0 | ✓ 네이티브 | ✓ 직접 구현 | ✗ 높음(포크 유지·GPL) |
| **4. 시스템 전역 EQ(CATap/eqMac)** | 낮음 | $0 | ✗ 전역/스테레오 | ✗ 채널별 아님, 전 앱 영향 | 낮음 |

- **결론:** DCP-o-matic 출력만 정밀 튜닝이 목표 → **경로 1·4는 부적합**(스테레오/전역). 현실 후보는 **3(포크)** vs **2(하드웨어 DSP)**.
- **시네마 B-chain 기준:** 8채널 독립 1/3옥타브 EQ + 채널별 레벨(−20dBFS 핑크 = 85dB SPL C-Slow) + LFE +10dB, X-curve(소형룸 변형) 타깃. Dolby CP650/750·Trinnov가 이를 구현.
- 출처: Rogue Amoeba KB(스테레오 한계), miniDSP/Trinnov, SMPTE ST 202/RP 200, Dolby 매뉴얼.
