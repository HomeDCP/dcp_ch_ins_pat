# 프로젝트 히스토리 · 의사결정 기록

> 이 프로젝트가 어떤 논의를 거쳐 현재 방향에 이르렀는지의 서사와 결정 로그.
> **작성일:** 2026-07-09

---

## 1. 진행 서사

### ① 최초 구상 — 아이폰 기반 룸튜닝 솔루션
소스기기(1차 Mac, 2차 PC)의 출력 스피커(2.0/2.1/5.1/7.1)를 아이폰으로 측정·룸튜닝하고, 결과를 시스템 출력에 반영하는 앱. 초기엔 "웹앱이 맥에 권한 요청" 형태를 구상했으나, EQ 반영을 위해 추가 앱 설치가 불가피할 수 있다고 예상.

### ② 딥리서치 (음향학·측정·하드웨어·통합)
제어된 워크플로로 6개 토픽 + 5개 핵심주장 적대적 검증 수행:
룸튜닝 이론 / 측정·보정 / 멀티채널 캘리브레이션 / 아이폰 마이크 / macOS 통합 / iOS 프레임워크.

### ③ 검증으로 뒤집힌 전제
"시스템 전역 EQ에 가상 오디오 드라이버 필수"는 **부정확**으로 판명 → **macOS 14.2+ Core Audio Taps로 드라이버 없이 가능**. 사용자의 "경량화" 직관이 옳음이 확인됨.

### ④ 핵심 결정 4건 확정 (사용자 승인)
D1~D4 (아래 결정 로그).

### ⑤ 개발환경 정리 + 실제 리그 반영
입문자용 셋업가이드 작성. 실제 리그 확정: **M4 Max Mac Studio(macOS 26.5.1, 36GB) + iPhone 16(USB-C)**.

### ⑥ 개발환경 구축 착수
Xcode 미설치 확인(핵심 관문), 나머지 토대(CLT/git/brew/Swift)는 구비. **Phase D(git 초기화·.gitignore·초기 커밋) 완료.** Xcode 설치는 사용자 GUI 작업으로 대기.

### ⑦ 방향 전환 — DCP-o-matic 특화
사용자 실제 니즈가 **DCP-o-matic Player로 트는 영화 출력만 정밀 청취/튜닝**임이 드러남. "시스템 전역 대신 특정 앱만" + "포크가 편하지 않을까?" 제기. 이는 사실상 **극장 B-chain(상영관 EQ)을 소프트웨어로 만드는** 방향.

### ⑧ 리서치 — EQ 적용 4경로 + DCP-o-matic 내부구조
- **Audio Hijack류는 스테레오 파이프라인 한계** → 5.1/7.1 디스크리트 B-chain 실격.
- DCP-o-matic 코드: 재생 콜백(`film_viewer.cc`)에 **깨끗한 재생전용 EQ 삽입 지점** 확인(수출 DCP 오염 없음). GPL-2.0-or-later. 빌드는 어려움(osx-environment+cdist+패치FFmpeg), 단 **패치 FFmpeg는 우리 용도엔 생략 가능**.
- 현실 후보: **DCP-o-matic 포크** vs **하드웨어 DSP(miniDSP)**.

### ⑨ 현재 결정점 — 빌드 게이트
"macOS에서 순정 DCP-o-matic 소스빌드가 되는가"를 게이트로. 성공 시 포크 확정, 실패 시 하드웨어 DSP 선회. **빌드 계획 수립 완료, 실제 빌드는 사용자 요청 시 함께 진행.**

## 2. 결정 로그

| ID | 결정 | 상태 | 근거 |
|----|------|------|------|
| D1 | iPhone 프론트엔드 = 네이티브 iOS 앱(SwiftUI) | 확정 | measurement 모드·USB-C 마이크·vDSP·로컬네트워크 완전접근 |
| D2 | 마이크 = 내장 우선 + USB-C 외장 계측마이크 옵션 | 확정 | 진입장벽↓ + 정밀경로(오차 주원인=마이크) |
| D3 | v1 채널 = 2.0/2.1 (5.1/7.1 확장설계) | 확정 | 저역/서브 정합 핵심가치 집중, 빠른 출시 |
| D4 | 최소 macOS = 14.2+ | 확정 | Core Audio Taps로 드라이버·재부팅 불필요(경량화) |
| D5 | Apple Developer Program = 무료로 시작 | 확정 | 실기 테스트 가능, M2~M4에 $99 전환 |
| D6 | 개발환경 종료지점 = 빈 앱 실행(E2E 검증)까지 | 확정 | 서명·기기신뢰 리스크 선제거 |
| **P1** | **적용 경로: DCP-o-matic 포크 vs 하드웨어 DSP** | **평가 중** | 빌드 게이트 결과로 확정 예정 |
| G1 | DCP-o-matic 소스빌드 성공을 P1 게이트로 | 확정 | 빌드되면 포크가 우아, 안 되면 하드웨어 DSP |

> **주의:** ⑦ 이후 프로젝트 초점이 "범용 시스템 룸튜닝 앱"에서 "**DCP-o-matic 영화 출력 정밀 튜닝(소프트웨어 B-chain)**"으로 좁혀졌다. 기존 iOS 앱 명세([개발명세서.md](개발명세서.md))는 *측정 두뇌* 부분에서 여전히 유효하나, *EQ 적용* 부분은 P1 결정에 따라 재정의된다.
